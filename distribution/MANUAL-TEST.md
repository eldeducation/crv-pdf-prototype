# APIを使わないテスト

このモードでは外部AIのAPIへ接続せず、同じPipelineのAI呼び出し箇所を
ファイルの書き出し・取り込みに置き換える。通常の根拠・画像・内容照合・
紙面検査・完了承認の条件はそのまま適用する。APIキーを設定する必要はない。

## 画面での順序

1. ページを再読み込みし、先頭の「実行方法」で「APIを使わないテスト」を選ぶ。
2. 動画を選ぶかYouTubeリンクを指定し、用途・詳しさ・出力言語・希望を設定する。
   金魚のように解説音声がない動画では「解説音声がない動画」にチェックする。
3. 「テストを開始する」を押す。動画の取得・画像抽出後、回答待ちになる。
   回答待ちは計算中ではなく、チャットで作った回答JSONの取り込み待ち。
   そのまま待っても進まない。「次の操作へ」から入力の保存・回答の取り込みへ進む。
4. 「1. 指示・画像をまとめて保存」でZIPを保存し、展開する。
   request.jsonにsystem・messages・tools、images/にすべての入力画像がある。
   request.htmlは会話順の文章・画像・操作仕様を閲覧するための静的ファイル。
   画像の重複はファイル単位で共有するが、会話中の出現位置・順序は保存する。
5. チャットにこの依頼を渡し、全画像と指示に従った回答JSONを作る。
   response-template.jsonのrequest_idを変えず、tool_callsにnameとinputを記載する。
   inputはrequest.json内のtools[].input_schemaに従う。回答例・承認結果は自動生成しない。
6. 「3. 回答JSONを選ぶ」でそのファイルを指定し、「回答を読み込んで続ける」を押す。
   request_idが古い、操作が不許可、形式が不正な回答は待機中のまま修正できる。
   意味や根拠の検査で不備があれば、次の依頼にエラーが含まれるので修正して提出する。
7. 必要な画像の追加確認、内容案、資料作成、内容照合、紙面確認の依頼ごとに繰り返す。
   通常の条件を満たした時点でPDF・Markdownを保存できる。

待っている間は処理元PCとサーバーを起動しておく。「追加処理を止める」で
待機を終了できる。再起動した場合は保存状態と版を確認して「途中から再開する」。
APIなしで開始した生成を、途中からAPI生成へ切り替えることはできない。
チャットがこのPCのファイルを読める場合は、開発者が同じ依頼・回答を扱うこともできる。
サイトからチャットへ自動で接続する機能ではない。

## 記録と限界

- runs/<id>/manual/<sequence>-<短縮ID>/に依頼と回答を保存する。
  これには動画の抽出画像と資料内容が含まれる。APIキーを含めない。
- manual-exchanges.jsonは手動で回答した履歴。API利用記録とは分ける。
- run.jsonのmanual_mode=true、provider=manual、live_ai=falseで明示する。
  API呼び出し0回・料金0を記録する。チャット側の利用枠はこの集計に含めない。
- 手動テスト中、画面のAPIモデル・推論設定・費用目安は適用しない。
  チャットで使うモデルや会話履歴が違うため、APIの品質・出力制限・通信は再現しない。
  このモードは特定のモデルを起動せず、回答を作成したチャットのモデルが働く。
  チャット側の正確なモデル名・推論設定は自動取得・実行記録への保存をしていない。
- 金魚動画は既知の失敗の再検証用。汎用的な改善の評価には未使用の動画も必要。

## 実装の検証

python -m unittest discover -s video_pdf_app/tests -v

tests/test_manual_mode.pyは画像の損失のない書き出し、回答・操作・識別子の検査、
CSRF、停止、実際のPDF出力、意味検査による差し戻し、APIへの切替拒否を確認する。
テストでは外部AIの通信を禁止する。見本の回答を使うため、AIの生成精度の証拠ではない。
tests/manual_browser_host.pyとtests/check_manual_ui.cjsは、同じ禁止条件の下で
画面からZIP保存・回答読み込み・日英切替・PDF保存・停止を確認する。
