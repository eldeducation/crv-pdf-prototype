# 2026-11-12：作業手順書の改善・Windowsでの使い方・チャットモード・フォルダー整理

## 作業手順書（用途 procedure）の改善
- **書き方ルール**（`editor.txt` の【作業手順書の書き方】）：■1 必ず守ること（です・ます調で言い切る、意味・数値・覚え方を変えない、出どころや確認作業を本文に書かない、通し番号1種類）、■2 目指す姿と良いやり方（手順の粒度を「省くと失敗するか・前提になるか・同時に行うか・話者が強調したか」で判断、音声の実用情報も使う、続く条件は1回だけ）、■3 よくある失敗と直し方。
- **例の扱い**：ルール中の例はすべて架空の作業（卓上ライトの電球交換）で、「書き方の型の説明であり、語句・数・順番・覚え方を持ち込まない」と明記。例にしか出てこない語句が資料に入り、内容案にない場合は差し戻す検査を追加（`pipeline.py`）。
- **デザイン方針**：表紙の主役写真と強調語、手順の前に全体の流れ（.chevrons）、各手順は大番号＋段階名＋動作の見出し（.chapter）で同じ型、主役の写真1枚を大きく、POINTは各手順1つまで。
- **用途の説明**（`document_options.py`）：内容整理の段階から、実演だけの動きを独立した工程にしない、覚え方・数値は表記のまま記録する。
- **工程チェック**（`presentation_quality.py`）：表紙・要点・まとめで手順を振り返っても差し戻さない。エラーに何ページ目のどの工程かを表示。
- **出典表示**（`pipeline.py`・`web_research.py`）：同じ外部資料は1ページ1回。作業手順書では、出典の時刻と外部資料名を本文ではなくページ下の欄にまとめる。
